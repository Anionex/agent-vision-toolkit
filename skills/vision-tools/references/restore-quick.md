# 非精确模式（默认）

触发信号：用户未提“像素级/精确”，只要求“布局、配色、图标一致”“大致还原”“复原 UI”。
工作目标：一眼看过去与原图一致即可，不为 1px 级细节投入。

## 步骤

1. **一轮 inventory**：`detect` 全屏一次，拿全部元素、文字和坐标；需要定位单个元素时用 `ground`。
2. **一轮 glance**：整体结构、图标形状、元素类型；个别看不清的小元素再 `glance --region` 一次。
3. **一轮颜色采样**：`scripts/dominant_colors.py` 对主要区域批量取色（背景、文字、图标主色），每个区域只取主色值，不纠结次色、渐变和 1px 细节。
4. **直接写 HTML/SVG**：坐标用 detect/ground 给的盒子直接换算近似（先确认 HiDPI 比例，见 restore.md 通用经验；2x 截图一律除以 2）；圆角用常见值（8/12/14px）；文字用系统字体近似。
5. **图标/logo 优先裁原图**：用 detect/ground 给出的 box 直接 `crop` 裁剪成 PNG（裁剪前按通用经验外扩 8~10px；浅色背景元素裁出来放在同色底上无缝），HTML 里 `<img>` 引用——图标与原图 100% 一致且零手绘成本。只有用户明确要求 SVG/矢量交付，或裁出的素材带明显背景色时才手绘 SVG。

## 修什么、不修什么

这一栏决定你在验证后还会不会“再修一轮”。只修**一眼可见**的问题；凡是需要放大或量出来才能发现的问题，都不修。

| 修（一眼可见） | 不修（1px 级细节） |
|---|---|
| 元素整体不在预期区域（错位超过半个元素） | 2~5px 的间距、边距差异 |
| 图标明显过大/过小、变形 | 圆角精确半径、阴影透明度 |
| 颜色明显不对（主色不同） | 1px 边框色、次色、渐变 |
| 文字换行明显不同、内容缺失 | 字体渲染差异（SF Pro vs Helvetica） |

## 验收（一次，不迭代）

1. 渲染：HTML 用 `scripts/html_shot.py`（或 Playwright），SVG 用 `rsvg-convert`。
2. 把渲染图与原图缩放到同尺寸，**并排拼成一张图**，用 `glance` 目检一次——这是本模式唯一的视觉对比方式。
3. 无一眼可见差异即完成，停止。

除非用户要求，否则明确禁止：

- 用 pixel_diff 逐轮迭代——最多跑一次当参考数字，不要按 worst regions 排名继续修。
- 用 `trace` 抠图标或轮廓（直接裁剪原图即可）。
- 反复扫描同一区域的色值变化或位置细节。
- 因为字体渲染差异等已知噪声而升级精确模式。
