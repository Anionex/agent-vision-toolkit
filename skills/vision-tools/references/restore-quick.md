# 非精确模式（默认）

触发信号：用户未提“像素级/精确”，只要求“布局、配色、图标一致”“大致还原”“复原 UI”。
工作目标：一眼看过去与原图一致即可，不为 1px 级细节投入。

## 步骤

1. **一轮 inventory**：`detect` 全屏一次，拿全部元素、文字和坐标；需要定位单个元素时用 `ground`。
2. **一轮 glance**：整体结构、图标形状、元素类型；个别看不清的小元素再 `glance --region` 一次。
3. **一轮颜色采样**：`scripts/dominant_colors.py` 对主要区域批量取色（背景、文字、图标主色），每个区域只取主色值，不纠结次色、渐变和 1px 细节。
4. **直接写 HTML/SVG**：坐标用 detect/ground 给的盒子直接换算近似（先确认 HiDPI 比例，见 restore.md 通用经验；2x 截图一律除以 2）；圆角用常见值（8/12/14px）；文字用系统字体近似。**禁止用逐像素扫描**（PIL 逐行采样 RGB 找元素边界/校准坐标）来验证或修正 detect/ground 的 box——detect/ground 的 ±10~20px 偏差就是本模式接受的噪声上限，直接用、不要重测；重测边界属于精确模式的活儿。
5. **图标/logo 一律抠图，不许手绘 SVG**：按 `restore.md` 通用经验中的「从截图提取图标前景」流程做——`crop --scale 4` 裁出区域后 `scripts/extract_fg.py` 自动模式只传图即可（或用主色 union 兜底）；提取出的前景 PNG 用 `<img>` 引用，图标与原图 100% 一致。
   - **"图标太小、模糊、难抠"不是手绘的理由**：抠图是像素级复制原图，不做任何重绘，不存在降质；手绘 SVG 才会引入走样、比例失真和配色偏差。图标再小也能抠（放大 4x 再 ground/extract，见 restore.md）。
   - 手绘 SVG 只允许一种情况：**用户明确要求 SVG/矢量交付**（且此时通常已属精确模式，见 `restore-exact.md`）。

## 修什么、不修什么

这一栏决定你在验证后还会不会“再修一轮”。只修**一眼可见**的问题；凡是需要放大或量出来才能发现的问题，都不修。

| 修（一眼可见） | 不修（1px 级细节） |
|---|---|
| 元素整体不在预期区域（错位超过半个元素） | 2~5px 的间距、边距差异 |
| 图标明显过大/过小、变形 | 圆角精确半径、阴影透明度 |
| 颜色明显不对（主色不同） | 1px 边框色、次色、渐变 |
| 文字换行明显不同、内容缺失 | 字体渲染差异（SF Pro vs Helvetica） |

## 验收（一次，不迭代）

1. 渲染：HTML 用 `scripts/html_shot.py`（或 Playwright），SVG 用 `rsvg-convert`。
2. 把渲染图与原图缩放到同尺寸，**并排拼成一张图**，用 `glance` 目检一次——这是本模式唯一的视觉对比方式。
3. 无一眼可见差异即完成，停止。

除非用户要求，否则明确禁止：

- 用 pixel_diff 逐轮迭代——最多跑一次当参考数字，不要按 worst regions 排名继续修。
- 用 `trace` 抠图标或轮廓（直接裁剪原图即可）。
- 因"图标太小/模糊/难抠"而手绘 SVG——抠图不降质，手绘才失真。
- 反复扫描同一区域的色值变化或位置细节。
- 因为字体渲染差异等已知噪声而升级精确模式。
