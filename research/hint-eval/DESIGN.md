# focus hint 效果评测 — 设计与预注册

2026-08-04 · 小规模 pilot

本文在**看到任何结果之前**写完并提交。预测写在下面，跑完不改。
目的是让「hint 有效」这句话第一次有可证伪的形式。

## 要回答的问题

README 现在的主张是：hint 让描述「贴合当前任务」。这只是对机制的描述，
没有任何数字支持「所以答得更准」。本次要给出的是：

1. 端到端问答准确率，hint 组 vs 无 hint 组，差多少。
2. 这个差是不是来自 hint 本身，而不是来自我们 prompt 里其它部分。
3. 离「直接用多模态模型」还差多远。
4. **hint 组的描述是不是在替主模型作答**——README_CN 亮点里写了
   「视觉模型只负责看，不替你推理」，这条要么被验证，要么被推翻。

## 四个条件

`vision_client.DEFAULT_PROMPT` 与 `codex-vision-proxy.py` 里的
`_ROLE_PROMPT` / `_DESCRIBE_PROMPT` / `_HINT_LABELS` 逐字取用，不另写副本。

| 条件 | 视觉侧 prompt | 代表什么 |
|---|---|---|
| `naive` | `DEFAULT_PROMPT`（"Please describe the contents of this image in detail."） | 普通转接方案 |
| `contract` | `_ROLE_PROMPT` + `_DESCRIBE_PROMPT`（无 hint） | 本项目的 prompt，但摘掉 hint |
| `hint` | `_ROLE_PROMPT` + hint + `_DESCRIBE_PROMPT` | **本项目实际行为** |
| `ceiling` | 视觉模型直接看图作答，无描述环节 | 多模态上限（Prism 式对照） |

`naive → contract` 分离出 prompt 契约的贡献；`contract → hint` 分离出 **hint 本身**的贡献。
只跑两条会把两者混在一起，得出的数字无法归因。

四个条件共用同一 `max_tokens=4096`。描述长度不设限也不设下限——
如果 hint 组靠更长的描述取胜，那是它的成本，要在结果里如实报出。

## 两级指标

- **端到端准确率（主指标）**：描述交给 `deepseek-v4-flash`（用户 Codex 里实际在用的
  纯文本模型），只给描述和问题，不给图，答案与标准答案比对。
- **关键事实覆盖率（机制指标）**：每题预先写死一条「答对它必须包含的事实」，
  判定描述里有没有。准确率告诉我们有没有提升，覆盖率告诉我们提升从哪来。

## 题目分类与预注册预测

每张图 3 题，覆盖四类。**题目和标准答案在跑任何模型之前写完**，
标准答案来自图片来源（合成图来自我自己写的 HTML），不来自任何模型输出。

| 类别 | 问的是 | 预测 |
|---|---|---|
| `detail` | 密集画面里某个具体值（某行的耗时、某个字段的取值） | **hint 明显胜出** |
| `relational` | 需要对比画面两处（哪个更大、两边一不一致） | **hint 明显胜出** |
| `verbatim` | 某个元素的逐字文本（报错原文、某行代码） | **hint 可能反而落后** |
| `global` | 整体布局/风格 | **打平** |

`verbatim` 一项是故意留的反向预测：`research/2026-08-03-hint-ab-comparison.md`
记录过 hint 把独立的 verbatim 转写段挤掉。如果这里 hint 也输，
说明那次不是偶然，`_DESCRIBE_PROMPT` 要动；如果没输，那条 n=1 的担忧可以降级。
**一个哪里都赢的评测是设计失败，不是好消息。**

## 诚实性检查：描述是否在替主模型作答

hint 组的描述里带着问题本身，视觉模型有可能直接把答案写进描述，
主模型只是复述。这样端到端准确率会好看，但 README 那条
「视觉模型只负责看，不替你推理」就是错的（`_ROLE_PROMPT` 明确禁止代答）。

因此每条描述额外判一次：**它是给出了推导所需的事实，还是直接给出了结论。**
两种结果都要写进结论——如果 hint 组靠代答取胜，README 的亮点条目必须改。

## 统计

n=36 是 pilot 量级，只够看有没有信号，不够定精确效应量。

- 配对设计（同题同图跑四个条件），用 **McNemar 检验**比较配对的对/错翻转。
- 效应量报 **bootstrap 95% CI**（10000 次重采样）。
- 分类别的 n≈9，**只看方向，不做单类别显著性**。

## 已知局限（写在前面，不等审稿人问）

- 一个视觉模型（`gemini-3.5-flash`，与线上 proxy 一致）、一个主模型。换模型结论可能变。
- 合成图的标准答案精确，但可能比真实截图简单；因此混入仓库里的真实截图。
- 题目由我撰写，选题偏好无法完全消除。缓解手段是先定类别配额再出题，
  且把预期打平/预期落后的类别一并纳入。
- 判分用 LLM，与视觉模型、主模型都不同家族，避免自我偏好；判分结果需人工抽查。
