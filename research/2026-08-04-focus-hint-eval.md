# focus hint 机制层评测 — 结果

2026-08-04 · 设计与预注册见 `research/hint-eval/DESIGN.md`（写在看到任何数据之前）

## 一句话结论

**在单图问答这一层，本项目 prompt 里的每一个组件——角色契约、逐字转写条款、focus
hint——都测不出统计显著的准确率增益。**两种题面（四选一、开放式）、230 道题、
五个条件、全部配对检验 p ≥ 0.227。同时得到两条干净的正面结果：hint 不是靠写得更
长赢的（它更短更省），以及文字中转的代价是 3.2 倍延迟 / 2.1 倍 token。

这是零结果，不是失败的实验。它约束了 README 能怎么写：不能声称 hint 提升准确率。

## 跑了什么

| 条件 | 视觉侧 prompt | 隔离出的变量 |
|---|---|---|
| `naive` | "Please describe the contents of this image in detail." | — |
| `contract_noverbatim` | `_ROLE_PROMPT` + `_DESCRIBE_PROMPT`，切掉两处转写指令 | 角色契约 |
| `contract` | 上一条 + 逐字转写条款 | 转写条款 |
| `hint` | 上一条 + focus hint（**线上实际行为**） | hint 本身 |
| `template` | 上一条 + 已删除的场景模板 | 模板该不该加回来 |
| `native` | 视觉模型直接看图作答 | 文字中转的代价（上限） |

除 `native` 外，所有条件都把描述交给 `deepseek-v4-flash` 作答，**答题模型从不看图**。
视觉模型 `gemini-3.6-flash-low`；prompt 从生产代码现取（`main@803867c`），不手抄。

题库 230 题：CaptionQA 100 题四选一 + 同一批图题去掉选项的 100 题开放式 +
30 道合成题（标准答案来自生成图片的 HTML 源码）。四选一与开放式**分开报，不合并配对集**。

## 结果

### 准确率（配对子集，McNemar 精确检验）

四选一 n=130：

| 对比 | 差值 | 胜/负 | p |
|---|---|---|---|
| `naive` → `contract_noverbatim`（角色契约） | +1.5 pp | 2 / 0 | 0.500 |
| `contract_noverbatim` → `contract`（转写条款） | −0.8 pp | 2 / 3 | 1.000 |
| **`contract` → `hint`（主判断）** | **+0.8 pp** | **4 / 3** | **1.000** |
| `hint` → `native`（文字中转代价） | +2.3 pp | 4 / 1 | 0.375 |
| `hint` vs `template`（19 题） | 0.0 pp | 0 / 0 | 1.000 |

开放式 n=99：

| 对比 | 差值 | 胜/负 | p |
|---|---|---|---|
| `naive` → `contract_noverbatim` | −3.0 pp | 5 / 8 | 0.581 |
| `contract_noverbatim` → `contract` | +5.1 pp | 8 / 3 | 0.227 |
| **`contract` → `hint`（主判断）** | **−1.0 pp** | **5 / 6** | **1.000** |
| `hint` → `native` | +3.0 pp | 6 / 3 | 0.508 |

绝对准确率：四选一 92%–96%，开放式 76%–83%。

### 成本（配对子集均值，判分调用不计）

| 条件 | 秒/题（四选一） | 视觉 token | 作答 token | 描述字数 |
|---|---|---|---|---|
| `naive` | 7.6 | 2437 | 740 | 1879 |
| `contract_noverbatim` | 8.0 | 2756 | 848 | 2266 |
| `contract` | 7.6 | 2763 | 845 | 2284 |
| `hint` | 7.6 | 2741 | 765 | 2108 |
| `native` | 2.4 | 1645 | — | — |

## 三条能站住的结论

**1. hint 不是靠写得更长赢的。** 这是本轮唯一被正面证实的机制主张。`hint` 相对
`contract`：描述更短（2108 vs 2284 字，开放式 2435 vs 2683），视觉 token 更少
（2741 vs 2763），且让答题模型少推理 9%（765 vs 845 token）。「hint 只是让模型
多写、所以撞对更多」这个替代解释被排除——它是**更省**的那一条，只是省下来的部分
没有换成可测的准确率。

**2. 文字中转的代价：3.2 倍延迟、2.1 倍 token。** `native` 2.4 秒 / 1645 token
vs `hint` 7.6 秒 / 3506 token（描述 2741 + 作答 765），准确率差 2.3 pp 不显著。
这是本项目第一次有的具体代价数字，可以直接写进文档。

**3. 在有明确问题的单图问答上，prompt 工程测不出增益。**注意这句话的边界——
见下节。

## 为什么零结果不等于「这些组件没用」

**每道题都自带一个明确的问题，问题本身就锚定了要找什么。** 这恰恰替代了 hint 和
转写条款的一部分作用：题目已经告诉答题模型该在描述里找什么，描述侧再被告知一遍，
边际价值自然小。真实场景没有这个保证——用户粘一张图并不附带「请看第 47 行的报错」。

这条限制是**预注册时就写下的**（DESIGN.md「逐字转写条款」一节），不是事后找补。
预注册原文：负结果「只能说『在有明确问题的单图问答下测不出增益』，不能外推成
『删了它没事』」。

同理，本文测不到：追问依从性、`view_image` 场景下以 assistant 意图作 hint 的路径、
以及任务成败。这三项归任务级评测。

## 题库为什么不够灵敏（两次尝试都失败）

**四选一有天花板效应。** 130 题里只有 10 题被任一描述条件答得不同。四个选项让答题
模型不需要描述真的**含有**答案，只需排除三个——而那个「含有」正是本评测要测的东西。

**开放式改造提升了区分度，但同时引入了更多标注噪音，净收益接近零。**
去掉选项后可区分题数从 10/100 升到 20/99，但预注册的剔除规则
（五个描述条件全错**且** `native` 也错 → 视为题面歧义）命中数从 1 题涨到 **10 题**。

| 题 | 标准答案 | 所有条件（含 `native`）的回答 |
|---|---|---|
| `doc_014_q0_open` | `σ1 and σ2` | 一律 `σ1, σ2, σ3` |
| `doc_105_q0_open` | `UC Berkeley, UT Austin, Toyota` | 一律答成「同等贡献 / 通讯作者」 |
| `doc_106_q0_open` | `From Range Image Block to...` | 答成「单向」「包含关系」 |

**`native` 是这条判断的证据**：一个直接盯着图、且拿着问题的模型也答不出来，说明这题
测的不是描述通道的保真度，是题目措辞。CaptionQA 的题面本来就是「配合四个选项才完整」
写的，抽掉选项不是变难，是变含糊。

按预注册要求，剔除前后两套数字都报（上表为剔除前；剔除后 n=89，准确率 84%–92%）。
**剔除不改变任何一个 head-to-head 的胜负计数**——全错的题是打平，McNemar 本就按构造
排除打平项，动的只有分母。

一条已排除的怀疑：检查了判分模型在近乎相同回答上的裁决，**零例自相矛盾**。判分模型
自洽，问题出在题目，不在判分。

## 预注册的预测，事后核对

| 预测 | 结果 |
|---|---|
| `document` 域 hint 明显胜出 | ❌ 打平 |
| `ecommerce` 域 hint 小幅胜出 | ❌ 打平 |
| `natural` 域打平，幻觉类可能落后 | ✅ 打平（2 胜 2 负），未落后 |
| `embodiedai` 域打平 | ✅ |
| 合成题大概率已饱和 | ✅ 30/30 全对，零区分度 |
| 合成题饱和则 `template` 裁决同时失效 | ✅ 生效——`template` 与 `hint` 有差异的 19 题里 16 题在合成集内 |
| 开放式大概率救不了这套评测 | ✅ |

**`template` 不能下结论。** 19 题全平，但其中 16 题落在已饱和的子集里，剩 3 题不足以
单独裁决。「模板不必加回来」这个判断本轮**没有**得到证据支持，也没有被推翻。

## 已知局限

- 一个视觉模型、一个答题模型，均与线上一致。换模型结论可能变。
- pilot 量级：n=130 / n=99 只够看有没有信号，不够定精确效应量。95% CI 全部跨过 0。
- CaptionQA 偏通用图像理解，与本项目真实场景（代码、终端、界面截图）不完全重合。
- 开放式判分约一半的行走 LLM 判定回退（`judge_used=true`）。
- **本文只覆盖机制层，结论不得外推到任务层。**
